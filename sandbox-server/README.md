# Pipeline Sandbox Server — разворачивание на своём сервере

Даёт игрокам Pipeline настоящий изолированный Linux-контейнер прямо в
браузере вместо симулятора — для миссий, где это уместно. Работает
только для вошедших в аккаунт (проверяется через тот же Supabase, что
уже использует игра).

## Что нужно на сервере

- Linux (любой современный дистрибутив)
- Docker + Docker Compose (`docker compose version` должен работать)
- Ничего больше — Node.js ставить не нужно, он внутри контейнера сборки

## Установка (5 команд)

```bash
# 1. Docker, если ещё не стоит
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && newgrp docker

# 2. Скопировать эту папку sandbox-server/ на сервер, затем внутри неё:
cp .env.example .env
# .env уже содержит правильные значения — трогать не обязательно

# 3. Заранее скачать образ песочницы (чтобы первый игрок не ждал)
docker pull alpine:3.20

# 4. Поднять сервис
docker compose up -d --build

# 5. Проверить, что живой (изнутри сервера)
curl http://localhost:8088/health
# должно вернуть {"ok":true,"active":0}
```

## Открыть наружу через Cloudflare Tunnel (бесплатно, без аккаунта)

```bash
curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared.deb
cloudflared tunnel --url http://localhost:8088
```

Появится строка вида:

```
https://random-words-1234.trycloudflare.com
```

Это и есть публичный адрес — пришлите его, я подключу игру к нему
(поле `SANDBOX_URL` появится в `p9.txt`/`p37.txt`, замените `wss://`
вместо `https://` и добавьте `/sandbox` в конце).

**Важно:** Quick Tunnel — временный, адрес меняется при перезапуске
`cloudflared`. Если сервис нужен постоянно (не только на сегодня для
теста), лучше запускать `cloudflared` через systemd-юнит, чтобы он
переживал перезагрузку и не давал вам вручную передавать новый адрес
каждый раз — либо (ещё надёжнее) завести бесплатный домен на Cloudflare
и настроить именованный туннель с фиксированным адресом. Могу помочь
с этим следующим шагом, когда первая версия подтвердит, что всё
работает.

## Что это НЕ делает (осознанно, ради безопасности)

- Не даёт сети внутри песочницы (`--network none`) — это ваш домашний
  IP, открывать его наружу для скачивания чего угодно из песочниц
  никто не будет
- Не даёт docker-in-docker или Kubernetes — только реальный Linux:
  процессы, файлы, права, текстовые утилиты
- Не даёт больше одной сессии на пользователя одновременно и не больше
  `SANDBOX_MAX_CONCURRENT` (по умолчанию 5) сессий на сервер разом —
  жёсткая защита от перегрузки вашей машины
- Автоматически убивает контейнер через `SANDBOX_MAX_MINUTES` (по
  умолчанию 15) или при закрытии вкладки — не копит забытые процессы

## Мониторинг

```bash
docker compose logs -f sandbox      # логи сервиса
docker ps --filter name=pipeline-sbx  # активные песочницы игроков прямо сейчас
curl http://localhost:8088/health     # число активных сессий
```
