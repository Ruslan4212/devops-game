# Terminal Ops Academy

Тренажёр DevOps с симулятором терминала: от первой команды в Linux до дежурства
по проду. Игрок печатает настоящие команды, а мир на них реагирует — файлы
создаются, службы падают, поды перезапускаются.

## Модель контента: урок из маленьких шагов

Курс построен как Duolingo/Boot.dev, а не как лекция. Единица — **урок**,
внутри — поток **шагов** одного из видов (`src/engine/types.ts`):

- `say` — короткая подводка, кнопка «Дальше»;
- `watch` — команда выполняется сама, игрок видит вывод и разбор («I do»);
- `type` — набери ровно эту команду, есть кнопка «Вставить» («We do»);
- `do` — своя маленькая задача; после 1 ошибки подсказка, после 2 — готовый
  ответ. Провалить нельзя («You do»);
- `quiz` — проверка понимания без печати.

Панель справа показывает **один текущий шаг**, а не список целей.

**Акт 1** (`src/lessons/act01.ts`) — 9 уроков, переписан вручную в этой модели.
**Акты 2–10** пока идут через `src/lessons/legacy-adapter.ts`: старые задания
из `src/missions/*` разворачиваются в шаги `say` + `do` (по одному на цель, с
авто-подсказкой). Их предстоит переписать так же вручную, по акту за раз.

## Команды

```bash
npm install          # один раз
npm run dev          # разработка с горячей перезагрузкой
npm test             # прогон эталонных решений всех заданий
npm run typecheck    # проверка типов
npm run build        # dist/        — статический сайт (Pages, Netlify, любой хостинг)
npm run build:single # dist-single/ — один самодостаточный .html, работает офлайн и с флешки
```

## Структура

```
src/
  engine/     ядро, не знает про DOM
    types.ts    все типы данных
    vfs.ts      виртуальная файловая система
    world.ts    начальное состояние мира
    shell.ts    разбор строки: конвейеры, редиректы, переменные
    runner.ts   прохождение задания и зачёт задач
    editor.ts   единая точка сохранения файла
    progress.ts XP, ранги, localStorage
  commands/   по одной подсистеме на файл: fs, text, system, net,
              git, docker, ci, terraform, k8s, monitoring
  missions/   act01.ts … act10.ts — учебный контент
  ui/         terminal, rail, briefing, editor — только отрисовка
tests/        missions.spec.ts
```

Правило: `engine/` и `commands/` не трогают DOM, `ui/` не знает про игровые правила.
Благодаря этому тесты гоняют настоящий движок без браузера.

## Как добавить задание

1. Открой нужный `src/missions/actNN.ts` и добавь объект в массив.
2. Обязательные поля: `why` (зачем это нужно), `cheat` (шпаргалка команд),
   `hints` (подсказки по нарастанию), `objs` (задачи с проверками) и **`solution`** —
   эталонное решение.
3. `npm test` — тест проиграет твоё решение и проверит, что все задачи закрываются.

`solution` — не формальность: без него задание может оказаться непроходимым,
и никто этого не заметит. Тест проверяет ещё и обратное — что задание нельзя
закрыть, не сделав ни одного действия.

## Проверки в тестах

- каждое из 23 заданий проходится эталонным решением;
- ни одно задание не засчитывается «само собой» после подготовки мира;
- у всех заданий есть брифинг, шпаргалка, подсказки и решение;
- идентификаторы уникальны, акты идут по порядку;
- суммарного XP хватает, чтобы дойти до верхнего ранга.

## Куда расти

Бэкенд не нужен, пока прогресс живёт в браузере. Он понадобится только для
синхронизации между устройствами, аккаунтов или общего рейтинга — и ляжет
тонким слоем поверх, статика останется статикой.

Ближайшее по ценности: PWA-манифест (установка на телефон, офлайн),
автодополнение команд по Tab, новые акты — Ansible, Prometheus/Grafana,
работа с секретами, канареечный деплой.
